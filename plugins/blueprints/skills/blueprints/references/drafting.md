# Drafting project memory

Load for new items, draft Specs, and draft or proposed Decisions. Apply the selected Project Memory rules.

1. Identify the meaning owned by the item and reuse its stable ID if it exists.
2. Write current desired intent in a Spec, in the present tense. Refine it in place as the user clarifies the same intent.
3. For an unresolved important choice, write or refine a draft Decision stating the problem and durable context. Once there is a concrete proposal, use `proposed` with a grounded Y-statement. Include only actually evaluated alternatives, and ask about material missing reasoning rather than inventing a downside.
4. Keep only information that changes how a reader acts, and omit empty sections. Split an item that outgrows the ~400-word body budget in Project Memory §4.
5. Add valid connections, with required reasons and Spec ownership ancestry. A folder-level Spec exists for shared intent, not a child inventory.

New Specs start `draft`; new Decisions start `draft` or `proposed`, according to whether there is a concrete proposal. Creation does not approve them. Advancement is a separate explicit approval under project authority. When an existing accepted choice is being reconsidered, keep that accepted record and current intent intact until the replacement is approved.

When Working Memory is active, use Explorations for useful unresolved implementation context. Link each to the Spec it explores, the draft or proposed Decision it informs, or both. An `informs` link alone is enough; do not create a Spec just to link one. Explorations carry no `status`, and a Decision must still read correctly once its Explorations are gone. When a linked Spec becomes active or a linked Decision is resolved, review its Explorations under Working Memory §7; the status change alone does not make one obsolete.

Repeated drafting does not produce an edit history, justification records, or Decisions about wording. Execution duration and running checks do not introduce additional item types. Keep task progress and results in the task's normal working records.
