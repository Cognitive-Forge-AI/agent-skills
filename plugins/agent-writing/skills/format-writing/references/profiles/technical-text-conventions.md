# Technical text conventions

Apply these defaults within technical passages; they do not impose a voice or regional spelling on the whole publication. Use sentence case for headings unless explicitly overridden. Preserve names, UI capitalization, identifiers, and normative keywords exactly.

Reserve bold for visible UI labels and run-in labels such as notices. Use italics sparingly for introduced terms or semantic emphasis; prefer wording that makes importance clear. Use inline code for filenames, commands, API members, parameter values, HTTP status codes, and other literal technical tokens. Use blocks for samples or console transcripts, preserving their content and supported language labels. There is no universal block-length limit.

Choose ordered lists for procedures, bullets for nonsequential items, and tables for aligned properties or comparisons. Use descriptive links and meaningful image alternatives; do not hide essential instructions in images or callouts. Follow the selected output syntax and renderer. Explicit formatting requirements override defaults, but incompatible mandatory requirements require resolution.
