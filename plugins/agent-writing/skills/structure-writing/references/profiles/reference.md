# Reference

Help experienced readers find a precise answer without following a lesson. Organize by the system's stable vocabulary, such as API members, configuration keys, commands, or concepts. Use consistent entry fields when comparable items share a contract.

State supported signatures, types, ranges, defaults, units, return values, errors, and version boundaries where applicable. Explain ambiguous semantics, especially counts, boundaries, and exceptional cases. Preserve normative keywords and exact examples. Missing fields remain unknown; completeness is not permission to infer behaviour.

Keep descriptions concise and factual. Put an example beside the fact it illustrates when it helps lookup. Separate usage guidance or theory when it would obscure the answer, linking only to actual destinations. A requested reference can be a paragraph or table; no fixed page template is required. Presentation rules determine code styling, heading capitalization, and table syntax.
