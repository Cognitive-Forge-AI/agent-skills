# Define writing brief

Make the writing requirements usable without turning a small request into an interview. Reuse audience, purpose, voice, length, and format already supplied. A brief can be a sentence when that is enough.

## Procedure

1. Record audience and prior knowledge, purpose, intended reader outcome, scope, source context, and constraints. Distinguish required content from optional ideas. Preserve exact wording, examples, regional spelling, and user-defined voice where requested.
2. Choose profiles only where they help the task. Medium is the publication setting; structure is the reader's task; style is the prose register; presentation is syntax or text conventions. A blog may use Markdown. Documentation may use another renderer.
3. When selecting bundled profiles, read [profile selection](references/profile-selection.md), then only the chosen profile files. Multiple presentation profiles may coexist when their scopes differ. Do not load every profile to choose one. For a user-supplied profile, record its axis and scope.
4. Apply explicit user requirements above profile defaults, subject to higher-priority instructions. Profiles govern only their axes; they cannot override facts or voice. Surface incompatible requirements with their sources. Ask for a choice when two mandatory rules cannot both be satisfied; do not silently pick a winner. Continue only independent work while the conflict remains.
5. Ask only about missing information that materially affects the writing. Otherwise state a reasonable assumption briefly. Without selected profiles, use the requested medium, a reader-appropriate progression, the user's voice, and the requested output format. Do not require profile selection to proceed.

## Output and composition

Return a concise brief including selected profile IDs or paths and unresolved conflicts. Keep it in conversation unless persistence helps. Read [handoffs](references/handoffs.md), brief section only, when another capability needs a shared handoff.

If source collection is needed, read [build-writing-context](../build-writing-context/SKILL.md) before using it. Otherwise use the supplied context. Do not produce an outline, draft, or full review unless the user requests that work.
