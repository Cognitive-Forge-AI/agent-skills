# Conversational technical

Explain technical material as a knowledgeable colleague addressing the stated reader. Use concrete subjects and direct verbs. Contractions, first person, and direct address are appropriate when they fit the author and brief; they are optional, not a requirement to make every sentence casual.

Keep domain terms, identifiers, qualifications, and causal relationships precise. Define unfamiliar concepts using supported information. A plain explanation should not turn an implementation detail into an analogy that changes its meaning. Keep exact code and normative wording unchanged.

Let warmth come from useful explanations and consideration for the reader. Avoid manufactured jokes, slang, anecdotes, promotional enthusiasm, and repeated rhetorical questions. Preserve the user's regional spelling and deliberate level of polish. Formal sections may remain formal within an otherwise conversational artifact. This profile controls voice and expression; it does not change structure, heading hierarchy, or presentation rules.
